1. 레이어 스택 로그 → 파생

로그(L0)만 진실. ①②③④는 전부 L0에서 파생되며 regenerate 가능. ①(식별·정체성)만 신중, ② 위로는 가볍다.

flowchart TB L0["L0 로그 레인<br/>append-only 진실<br/>Intent / Action / Observation / Verification"] N1["① 대상 노드 ObjectId<br/>타입 · 식별 · 정체성 계약"] N2["② Provenance<br/>resolve fold · 이력 · alias · 캐시"] N3["③ analyzer 구조 그래프<br/>코드 파싱 · 별도 id공간"] N4["④ OKG / 프로젝트맵<br/>② + ③ 합성 (file 축 조인)"] L0 -->|"targets ObjectId"| N1 N1 -->|"계약 실행"| N2 N2 --> N4 N3 -->|"코드 구조"| N4 classDef truth fill:#13303a,stroke:#39d0d8,color:#e6edf3 class L0 truth
핵심: 코드 구조(import/calls)는 ③ analyzer(별도 id공간), 의도·이력은 L0+② — 둘은 file: 경로를 공유 축으로 ④에서 조인.

2. 진실(L0) vs 파생(②③④) regenerate

flowchart LR subgraph T["진실 (보존)"] LOG["L0 로그<br/>append-only<br/>retract 금지"] end subgraph D["파생 (regenerate)"] PV["② Provenance"] AN["③ analyzer 캐시"] OKG["④ OKG"] end LOG -->|"fold"| PV LOG -.->|"dirty"| AN PV --> OKG AN --> OKG classDef truth fill:#13303a,stroke:#39d0d8,color:#e6edf3 class LOG truth
파생은 날아가도 L0 재fold로 복원 — 그래서 정확성만 신경 쓰면 되고 진실은 안 흔들림.

3. ① 대상 노드 — 7종 file + 로그네이티브 6

로그의 targets가 가리키는 대상. 저장 엔티티가 아니라 식별 규약(런타임 = 문자열 하나). 격하 기준 = regenerate 가능성.

flowchart TB OID["ObjectId<br/>type : canonical-id<br/>(런타임 = 문자열 1개)"] subgraph EXT["외부 소유 — 진실은 디스크/git"] F["file<br/>repo경로 · NFC · git sha"] end subgraph LN["로그 네이티브 — 진실은 로그 (ULID)"] T["task<br/>evidence-gated done 표적"] D["decision<br/>독립 추적 · supersede"] C["concept<br/>+ alias (도메인 용어)"] K["constraint<br/>DDD invariant"] CH["check<br/>+ verifies 대상"] I["issue<br/>level gate · filed_as<br/>(정합 반영 예정)"] end OID --> EXT OID --> LN
제외: method = 약참조(③ analyzer regenerate) · adr = file + decision 분해.

4. 식별 — ULID 발급 ↔ 조회 분리 v3.1 핵심 교정

ULID는 불변 앵커로는 견고하나 조회 키로는 못 써 → 두 역할 분리.

flowchart TB subgraph ISSUE["발급 (앵커)"] A["태어나는 로그가 ULID 발급<br/>decision.made → decision:01J…"] A2["✅ 결정적 · 불변 · 같은 ULID = 같은 대상"] A --> A2 end subgraph LOOKUP["조회 (수렴)"] B["라벨(payload.title) / alias 매칭"] B2["⚠️ best-effort · 비결정<br/>못 찾으면 새 발급 → 분기"] B --> B2 end ISSUE -.->|"두 역할 분리"| LOOKUP
목표 축소: "멀티 writer 키 일치"(불가) → "식별자 안정 + best-effort 수렴". check가 모범 — verifies 대상 좌표를 상속해 부분 수렴.

5. 정체성 연속 어휘 방향=payload

ObjectId는 그 시점 이름표. 변경도 명시 로그(자동추론 금지). 방향은 payload, targets는 순서 없는 집합.

6. ② resolve() — 정체성 fold ①§4 실행

L0 로그를 fold해 "현재 유효한 tip"을 결정론적으로 도출. tip = 종료 어휘에 소비 안 된 follows-DAG leaf.

v1 버그 수정: tip을 "전진 어휘 열거(amended/resumed)"로 정의했더니 weakened/strengthened가 빠졌음 → "종료 안 된 leaf"로 일반화해 자동 포함.

7. end-to-end — evidence-gated completion 시퀀스

8. 게이트 freshness ★ 안전 최우선

② 집계 캐시는 "진실 아님". 게이트가 그걸 믿으면 stale truth가 판정으로 부활 → 판정 입력은 항상 L0 직접 재fold.
